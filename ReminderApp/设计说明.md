# Android 手机个人提醒程序设计说明

## 1. 需求分析

| 编号 | 功能 | 说明 |
|---|---|---|
| F1 | 新建提醒 | 输入标题（必填）、备注，选择日期、时间、重复方式 |
| F2 | 提醒列表 | 按“启用优先、时间升序”展示全部提醒，空列表给出提示 |
| F3 | 编辑 / 删除 | 点击条目进入编辑；长按条目或在编辑页删除 |
| F4 | 启用 / 停用 | 列表中的开关可临时关闭某条提醒 |
| F5 | 到点通知 | 到达设定时间弹出高优先级通知（声音 + 振动），即使应用未运行、手机处于休眠 |
| F6 | 重复提醒 | 支持不重复 / 每天 / 每周 / 每月 |
| F7 | 稍后提醒 | 通知上提供“10 分钟后”和“知道了”按钮 |
| F8 | 可靠性 | 手机重启、应用更新、修改系统时间或时区后提醒依然有效 |

非功能需求：最低支持 Android 7.0（API 24），适配到 Android 14（API 34）；数据仅存本地，无需联网。

## 2. 总体架构

```
┌──────────────── 界面层 ────────────────┐
│ MainActivity        EditReminderActivity │
│   └ ReminderAdapter (RecyclerView)       │
└───────────────┬──────────────────────────┘
                │ 增删改查          │ 注册/取消闹钟
        ┌───────▼──────┐   ┌───────▼────────┐
        │  ReminderDb  │◄──┤ AlarmScheduler │──► 系统 AlarmManager
        │  (SQLite)    │   └───────▲────────┘          │ 到点广播
        └──────▲───────┘           │                   ▼
               │            ┌──────┴──────┐    ┌────────────────┐
               └────────────┤ BootReceiver│    │ReminderReceiver│
                            └─────────────┘    └───────┬────────┘
                                                       ▼
                                              NotificationHelper → 状态栏通知
```

| 文件 | 职责 |
|---|---|
| `Reminder.kt` | 数据模型 `Reminder`、重复类型 `RepeatType`（含下次时间计算） |
| `ReminderDb.kt` | SQLiteOpenHelper 单例，提供 getAll / getById / save / delete |
| `AlarmScheduler.kt` | 封装 AlarmManager：注册、取消、稍后提醒、全部重新注册 |
| `ReminderReceiver.kt` | 接收到点广播与通知按钮事件，弹通知并计算下一次 |
| `BootReceiver.kt` | 开机 / 应用更新 / 时间或时区变化后调用 `rescheduleAll` |
| `NotificationHelper.kt` | 创建通知渠道、构建带操作按钮的通知 |
| `MainActivity.kt` | 列表页、权限申请、开关与删除 |
| `EditReminderActivity.kt` | 新建 / 编辑页，日期时间选择与校验 |

## 3. 数据库设计

表 `reminder`：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | 主键自增 | 同时作为 PendingIntent 请求码与通知 ID |
| title | TEXT | NOT NULL | 标题 |
| note | TEXT | 默认 '' | 备注 |
| trigger_at | INTEGER | NOT NULL | 下一次触发时间（毫秒时间戳） |
| repeat | TEXT | 默认 'NONE' | NONE / DAILY / WEEKLY / MONTHLY |
| enabled | INTEGER | 默认 1 | 1 有闹钟等待触发，0 停用或已触发 |
| is_todo | INTEGER | 默认 0 | 1 待办，0 普通提醒（v2 新增） |
| done_at | INTEGER | 默认 0 | 待办完成时间，0 表示未完成（v2 新增） |

数据库版本 2：`onUpgrade` 中用 `ALTER TABLE ... ADD COLUMN` 增加后两列，原有数据都视为普通提醒。

设计要点：`trigger_at` 始终保存**下一次**触发时间，重复提醒每次触发后向前推进一个周期，因此重新注册闹钟时只需读这一列。

## 4. 关键流程

### 4.1 保存提醒
1. 校验标题非空；
2. 重复提醒若所选时间已过，自动推进到未来的最近一个周期（`rolledForward`）；一次性提醒时间已过则提示重新选择；
3. 写入数据库 → `AlarmScheduler.schedule()` 注册精确闹钟。

### 4.2 到点触发（`ReminderReceiver`）
```
收到 ACTION_FIRE(id)
 ├─ 查库，不存在或已停用 → 结束
 ├─ 弹出通知
 ├─ 一次性：enabled = 0
 └─ 重复：trigger_at 推进到下一周期 → 保存 → 再次注册闹钟
```

### 4.3 稍后提醒
通知按钮发送 `ACTION_SNOOZE` → 取消当前通知 → 10 分钟后以 `ACTION_SNOOZE_FIRE` 注册一个闹钟。使用不同的 action 使其成为独立的 PendingIntent，不会覆盖重复提醒原定的下一次闹钟。

### 4.4 重启恢复
AlarmManager 中的闹钟在关机后会丢失。`BootReceiver` 监听开机等广播，遍历所有启用的提醒：重复提醒推进到未来再注册；关机期间错过的一次性提醒标记为已完成。

## 5. 系统版本适配

| 版本 | 问题 | 处理 |
|---|---|---|
| 6.0+ Doze 省电 | 普通闹钟在休眠时被推迟 | 使用 `setExactAndAllowWhileIdle` |
| 8.0+ | 通知必须属于渠道 | 创建 IMPORTANCE_HIGH 渠道 `reminders` |
| 12 / 12L | 精确闹钟需用户授权 | 声明 `SCHEDULE_EXACT_ALARM`，未授权时引导到设置页，并降级为 `setAndAllowWhileIdle` |
| 13+ | 通知需运行时权限；提醒类应用可用 `USE_EXACT_ALARM` | 启动时申请 `POST_NOTIFICATIONS`；声明 `USE_EXACT_ALARM` |
| 12+ | PendingIntent 必须指定可变性 | 统一使用 `FLAG_IMMUTABLE` |

> 国产 ROM（小米、华为、OPPO 等）常有额外的“自启动”“后台运行”限制，需要用户手动在系统设置中允许本应用自启动，否则重启后的恢复和后台提醒可能失效。

## 6. 界面设计

**视觉风格**：浅灰背景（#F5F6F8）+ 白色圆角卡片（16dp 圆角、1dp 细边框、无阴影）；黑底白字的胶囊形筛选标签；蓝色强调色（#2F6BFF）；统计数字大号粗体。颜色统一定义在 `values/colors.xml`，`values-night/colors.xml` 提供深色模式配色。界面采用传统 XML 布局实现。

- **主界面**（自上而下）：
  - 顶部栏：左侧菜单（查找手机、智能识别设置、通知设置）、居中标题、右侧查找手机按钮（服务运行时带绿点）；
  - 筛选标签：全部 / 今天 / 重复 / 已停用；
  - 可横向滑动的统计卡片：今日待提醒（含下一条提醒）、已启用（含重复数）、查找手机状态；
  - 提醒列表卡片：每行为“圆形首字图标 + `时间 标题` + 重复方式/备注 + 启用开关”，时间按“09:30 / 明天 09:30 / 10月12日 09:30”友好显示；停用项半透明；
  - 右下角蓝色圆形悬浮按钮新建。
- **编辑界面**：顶部“智能识别”卡片（仅新建时显示，见第 11 章）；标题、备注输入框；识别出事件时间后出现的“提前量”标签；日期 + 时间按钮；重复方式标签（不重复 / 每天 / 每周 / 每月）；保存按钮；编辑已有提醒时显示删除按钮。
- **通知**：标题为提醒标题，正文为备注（无备注时显示时间），带“10 分钟后”“知道了”两个按钮，点击通知打开应用。

## 10. 扩展功能：查找手机

### 10.1 需求
在家找不到手机时，在笔记本电脑的网页上点一个按钮，手机以最大音量报警，**静音 / 振动模式下也要响**；完全离线，不依赖任何外部服务器。

### 10.2 方案
手机自身运行一个极简 HTTP 服务器（局域网内），电脑浏览器直接访问手机：

```
笔记本浏览器 ──(家庭 Wi‑Fi / 手机热点，无需互联网)──► 手机 :8080
  查找手机.html                                   FindPhoneService（前台服务）
   POST /api/ring  (X-Pin)                          ├ FindPhoneServer  解析请求、校验 PIN
                                                    └ AlarmPlayer      闹钟音频流播放警笛
```

路由器只负责转发局域网数据，断网也能用；没有路由器时，让电脑连手机热点即可。

| 文件 | 职责 |
|---|---|
| `findphone/FindPhoneServer.kt` | 基于 ServerSocket 的 HTTP 服务器，无第三方依赖 |
| `findphone/FindPhoneService.kt` | 前台服务：常驻运行服务器、持有 WifiLock、响铃 3 分钟自动停止 |
| `findphone/AlarmPlayer.kt` | 合成双音警笛，以闹钟流最大音量循环播放 + 振动 |
| `findphone/FindPhoneActivity.kt` | 开关、地址与 PIN 显示、权限引导、测试响铃 |
| `findphone/RingingActivity.kt` | 锁屏上全屏显示的“找到了”按钮 |
| `assets/findphone.html` / `laptop/查找手机.html` | 控制网页（同一份文件） |

### 10.3 静音下也能响的原理
1. **闹钟音频流**：以 `AudioAttributes.USAGE_ALARM` 播放。系统的静音 / 振动模式只作用于铃声流，闹钟流不受影响（这也是系统闹钟在静音下照样响的原因）；
2. **临时最大音量**：响铃前保存闹钟音量并调到最大，结束后恢复；
3. **勿扰模式**：“完全静音”类勿扰会拦截闹钟。用户授予“勿扰权限”后，响铃期间临时把勿扰切到“全部允许”，结束后恢复原状态；
4. **自行合成声音**：用 `AudioTrack` 实时生成 880/1320Hz 警笛，不依赖系统铃声文件是否存在。

### 10.4 找不到手机时如何知道手机地址
手机找不到时无法查看手机屏幕，因此电脑端必须**不依赖事先看到地址**：

| 手段 | 说明 |
|---|---|
| 自动扫描（默认） | 电脑网页依次扫描常见家用网段（上次地址所在网段优先），对每个 IP 请求 `GET /api/ping`，返回 `{"app":"findphone"}` 即为本机。64 路并发，每个网段约 6 秒 |
| 记住地址 | 扫描或连接成功后把地址存入浏览器 localStorage，下次直接使用；连不上时自动重新扫描 |
| 固定 IP（推荐） | 在路由器后台为手机做 DHCP 静态分配，地址永不变化。注意 Android 的“随机 MAC”对同一个 Wi‑Fi 是固定的，静态分配同样有效 |

`/api/ping` 不需要 PIN，因此扫描时不会把 PIN 发给局域网中的其他设备，也不会触发错误次数锁定。

### 10.5 安全
- 只监听局域网，外网无法访问（家用路由器 NAT 天然隔离）；
- 响铃 / 停止 / 状态接口必须携带 6 位随机 PIN（`X-Pin` 请求头），常量时间比较；
- 连续错 10 次锁定 60 秒，暴力猜测 100 万种组合约需 100 天；
- 可在手机上随时更换 PIN 或关闭服务。

### 10.6 后台保活与系统适配
| 问题 | 处理 |
|---|---|
| 进程被回收 | 前台服务 + 常驻通知，`START_STICKY` |
| Doze 下断网 | 前台服务进程不受 Doze 网络限制；申请忽略电池优化 |
| 熄屏后 CPU 休眠 | Wi‑Fi 芯片保持连接，收到发给本机的单播数据包时唤醒 CPU；服务器线程收到响铃指令后立即持有短时 WakeLock，防止开始播放前 CPU 再次休眠。`WifiLock` 仅作辅助（新系统熄屏时基本无效）。可选“保持唤醒”（常驻 PARTIAL_WAKE_LOCK）进一步降低风险，但更耗电 |
| 深度休眠响应慢 | 网页端扫描超时 3.5 秒、接口超时 10 秒，避免把慢响应误判为“找不到” |
| 厂商 ROM 熄屏断网 / 杀后台 | 代码无法绕过，需用户在系统设置中关闭“休眠时断开 WLAN”，并允许自启动、后台运行 |
| Android 14 前台服务类型 | `foregroundServiceType="specialUse"` 并声明用途 |
| 开机后恢复 | `BootReceiver` 在开机 / 应用更新后启动服务 |
| 锁屏时停止响铃 | 全屏通知 + `RingingActivity`（`showWhenLocked`）；也可在网页上停止，3 分钟后自动停止 |
| 浏览器跨域 | 本地 HTML（file://）调用手机需 CORS，服务器返回 `Access-Control-Allow-*` 与 `Access-Control-Allow-Private-Network` 头；新版 Chrome 首次访问局域网设备可能弹出“允许访问本地网络”，点允许即可 |

### 10.7 测试用例
| 用例 | 预期 |
|---|---|
| 手机静音 + 锁屏，电脑点“让手机响铃” | 最大音量警笛 + 振动，锁屏上出现“找到了” |
| 勿扰“完全静音”且已授予勿扰权限 | 仍然响铃，停止后勿扰恢复 |
| 电脑网页清空地址后点响铃 | 自动扫描找到手机并响铃，地址被记住 |
| 手机 IP 变化 | 首次请求失败后自动重新扫描并成功 |
| PIN 错误 | 提示 PIN 不正确；连续 10 次后提示稍后再试 |
| 无人处理 | 3 分钟后自动停止，音量恢复原值 |
| 路由器断开外网 | 功能正常 |
| 手机重启 | 服务自动恢复，可正常响铃 |
| 关闭“保持唤醒”，熄屏静置 2 小时以上（进入深度休眠） | 电脑点击后数秒内响铃；若失败，检查厂商 WLAN 休眠策略或开启“保持唤醒” |

### 10.8 局限与扩展
- 手机关机、没电、或不在同一局域网时无法使用；
- 部分国产 ROM 需手动允许“自启动 / 后台运行”；
- 可扩展：蓝牙 BLE 方案（手机作 BLE 外设，电脑 Chrome 用 Web Bluetooth 连接，无需 Wi‑Fi）；
- 可扩展：响铃同时闪光灯闪烁（`CameraManager.setTorchMode`），方便在暗处寻找。

## 11. 扩展功能：智能识别（大模型）

### 11.1 需求
把收到的牙科诊所提醒短信、医院预约确认邮件等文字粘贴进来，由大模型自动识别出事项和时间，生成提醒。

### 11.2 使用流程
```
点“+”新建 ──► 自动读取剪贴板填入识别框 ──► 文本像一条带时间的通知？ ──是──► 自动调用大模型
                                                  │否                         │
                                                  ▼                           ▼
                                           提示手动点“识别”       填入标题 / 备注 / 重复方式
                                                                  显示事件时间 + 提前量（默认提前 1 小时）
                                                                              │
                                                                     用户核对 ──► 保存
```
另一入口：在短信或邮件 App 中选中文字 → 分享 → “添加为提醒”，直接进入识别（`ACTION_SEND text/plain`）。

### 11.3 设计要点
| 要点 | 设计 |
|---|---|
| 识别后需确认再保存 | 大模型可能算错相对日期（如“下周三”），医疗预约出错代价高，因此结果只填入表单，由用户确认后保存 |
| 事件时间 ≠ 提醒时间 | 模型返回事件时间；界面提供“准时 / 提前30分钟 / 提前1小时 / 提前1天”，提醒时间 = 事件时间 − 提前量；事件时间写入备注首行 |
| 读取剪贴板的时机 | Android 10+ 只有窗口获得焦点后才能读剪贴板，因此在 `onWindowFocusChanged` 中读取 |
| 防止重复建提醒 | 保存成功后记录该段文本的哈希；下次新建时剪贴板内容相同则不再自动粘贴 |
| 防止误发敏感内容 | 剪贴板被系统标记为敏感（密码管理器复制的密码等）时不读取；文本不含数字或不像句子时不自动识别 |
| 兼容多家服务商 | 采用 OpenAI 兼容的 `/chat/completions` 接口，预置 DeepSeek、智谱 GLM、通义千问，也可自定义；不依赖 `response_format`，提示词要求只输出 JSON，程序从回复中截取 `{...}` 解析 |
| 时间换算 | 提示词中带上当前日期、星期和时区，让模型把“明天”“下周三”换算成具体日期；只有日期没有时刻时默认 09:00 并在备注中注明 |
| 提示词注入 | 待识别文本放在分隔符内并声明“只是数据”；即使被注入，结果也只是填入表单，需用户确认 |
| API Key 安全 | 用 Android Keystore 生成的 AES-GCM 密钥加密后存入 SharedPreferences，密钥无法导出 |
| 错误提示 | 401 Key 无效、402 余额不足、429 频率或额度、超时、无网络等分别给出中文提示 |

### 11.4 模块
| 文件 | 职责 |
|---|---|
| `ai/AiConfig.kt` | 接口地址、模型名、加密的 API Key、最近识别文本哈希 |
| `ai/SecretStore.kt` | Keystore 加解密 |
| `ai/AiParser.kt` | 构造提示词、调用接口（HttpURLConnection + 协程）、解析 JSON |

### 11.5 模型输出格式
```json
{"found": true, "title": "洗牙复查", "datetime": "2026-10-14 10:30", "repeat": "NONE",
 "note": "地点：人民路88号3楼\n携带身份证，提前10分钟到达\n改约电话：010-12345678"}
```

### 11.6 费用与隐私
- 识别一条短信约消耗几百个 token，费用很低；DeepSeek 按量计费，新账户可能有赠送额度，部分平台提供免费模型，以各平台公告为准；
- 识别时文本会发送到所选服务商；“查找手机”功能完全离线，而智能识别需要联网。

### 11.7 测试用例
| 用例 | 预期 |
|---|---|
| 复制牙科预约短信后点“+” | 自动粘贴并识别，标题、备注、时间填好，默认提前 1 小时 |
| 短信写“下周三上午10:30” | 日期换算正确（需核对星期） |
| 只写日期没写时刻 | 时间为 09:00，备注注明“原文未写具体时间” |
| 预约在 40 分钟后 | 自动改为“准时” |
| 保存后再次点“+” | 不再自动粘贴同一条短信 |
| 剪贴板是一串密码 | 不自动识别（或因敏感标记不读取） |
| 未配置 API Key | 提示“还没有配置大模型，点此设置” |
| Key 错误 / 断网 | 显示对应中文错误，不影响手动填写 |
| 从短信 App 分享文字到“添加为提醒” | 直接进入识别 |

## 12. 扩展功能：待办（To-do）

### 12.1 需求
把工作上的事（如“客户来邮件要报价”）随时记进来，到时间提醒去完成；输入时直接用手机输入法的语音输入，App 不单独做语音识别。

### 12.2 提醒与待办的区别
| | 普通提醒 | 待办 |
|---|---|---|
| 典型内容 | 就诊、会议、预约 | 报价、回邮件、交报告 |
| 到点后 | 提醒一次即结束 | 仍保留，显示为“已逾期”（红字），直到勾选完成 |
| 列表左侧 | 彩色首字图标 | 完成圆圈，点击即完成，标题加删除线 |
| 列表右侧 | 启用开关 | 无 |
| 通知按钮 | 10 分钟后 / 知道了 | 10 分钟后 / 完成 |
| 识别出的时间 | 事件时间，可选提前量 | 直接作为提醒时间 |

状态判定：`isDone = done_at > 0`；`已逾期 = 待办 且 未完成 且 trigger_at ≤ 当前时间`。
重复待办勾选完成时，本次算完成并跳到下一个周期（如每周周报提前写完，下周照常提醒）。

### 12.3 语音录入流程
```
点“+” ──► 剪贴板有 15 分钟内复制的新内容？ ──是──► 自动粘贴并识别（邮件、短信场景）
                    │否
                    ▼
        识别框获得焦点、自动弹出键盘
                    │
        点输入法的麦克风，说“明天下午三点前给王总报价，A 型号 500 台”
                    │
        点“识别” ──► 大模型判断为待办，填入：
                     类型 待办｜标题 给王总报价｜时间 明天 15:00｜备注 A 型号 500 台
                    │
        核对 ──► 保存
```
- 只自动粘贴 15 分钟内复制的内容（依据 `ClipDescription.getTimestamp()`，Android 8.0+），避免把很久以前复制的东西带进来；
- 没提到时间时（如“给客户报价”），默认 1 小时后（取整到 5 分钟）提醒，并提示用户可修改。

### 12.4 提示词变化
- 输入不再只是短信 / 邮件，也可能是用户自己说的一句话；
- 新增 `type`：要自己去做的事为 `todo`，固定时间发生、需到场参加的为 `event`；
- 待办只给截止时间（“周五前”“下班前”）时以截止时间为提醒时间；完全没提时间时 `datetime` 为 `null`；
- 标题保留关键的人名、客户名、产品名，备注提取金额、型号、联系人等。

### 12.5 主界面
- 筛选：全部 / 今天 / 待办 / 重复 / 已完成；
- 排序：逾期待办在最前，其次等待中的提醒，再次已停用的；
- 统计卡片“待办事项”：未完成数量，副标题依次显示“N 项已逾期”（红色）/“N 项今天到期”/“都还没到期”；点击卡片切换到“待办”筛选。

### 12.6 测试用例
| 用例 | 预期 |
|---|---|
| 语音输入“明天下午三点前给王总报价” | 识别为待办，明天 15:00，标题含“王总” |
| 语音输入“给客户报价”（无时间） | 待办，默认 1 小时后，提示可修改 |
| 待办到点后不处理 | 列表中红字“已逾期”，排在最前，统计卡片显示逾期数 |
| 列表中点圆圈 | 标题加删除线、移入“已完成”，闹钟取消 |
| “已完成”中再点圆圈 | 恢复为未完成；时间未到则重新设置闹钟 |
| 通知上点“完成” | 待办标记完成，通知消失 |
| 每周待办提前勾选完成 | 提示下次时间，跳到下一周 |
| 剪贴板里是一小时前复制的内容 | 不自动粘贴，直接弹出键盘 |
| 旧版本升级 | 原有提醒保留，均为普通提醒 |

### 12.7 逾期待办每日提醒（静音）
| 项 | 设计 |
|---|---|
| 时间 | **用户可设置**（菜单 → 设置），默认每天 10:00，可整体关闭。全局只注册一个闹钟（`ACTION_OVERDUE_CHECK`），触发后检查并安排第二天；开机、修改时间 / 时区、打开 App、修改设置时都会重新注册（重复注册只覆盖，关闭时取消） |
| 范围 | 未完成、且在**今天之前**就已到期的待办。今天到期的在到期时已响过铃，今天不再重复，从次日设定时间起每天提醒 |
| 设置存储 | `AppSettings`（SharedPreferences）：`overdue_enabled`（默认 true）、`overdue_hour`（默认 10）、`overdue_minute`（默认 0）；时间选择器跟随系统 12 / 24 小时制 |
| 方式 | 独立通知渠道“逾期待办”：`IMPORTANCE_DEFAULT` + 无声音 + 无振动，只显示在状态栏、通知栏和锁屏；Android 8.0 以下用 `setSilent(true)` |
| 内容 | 标题“待办逾期：给王总报价”，正文“已逾期 2 天 · 原定 10月8日 15:00”+ 备注；按钮“完成” |
| 不堆积 | 与该待办的到期通知使用同一通知 ID，新的替换旧的 |
| 锁屏隐私 | `VISIBILITY_PRIVATE` + 公开版本：系统设为“隐藏敏感内容”时，锁屏只显示“有待办已逾期” |
| 停止条件 | 勾选完成（列表或通知上的“完成”）后不再提醒 |

说明：用户可在系统的通知设置中单独调整“逾期待办”渠道；若手动把它改为有声音，则以用户设置为准。

| 用例 | 预期 |
|---|---|
| 昨天到期的待办未完成，今天到达设定时间（默认 10:00） | 出现静音通知（不响铃、不振动），锁屏可见 |
| 今天 9:00 到期的待办，今天 10:00 | 不提醒；明天 10:00 起提醒 |
| 设置中把时间改为 08:30 | 次日 08:30 提醒；若今天 08:30 未到则今天即生效 |
| 设置中关闭开关 | 不再出现逾期通知；重新打开后恢复 |
| 通知上点“完成” | 标记完成，次日不再提醒 |
| 手机开着静音 | 通知照常静默出现 |
| 手机开着勿扰 | 取决于勿扰设置：若勿扰设为“隐藏通知”，则状态栏 / 锁屏可能不显示，但通知栏下拉仍可看到 |
| 重启手机后 | 设定时间的检查仍然生效 |

## 13. 到点响铃与真机适配（OPPO / ColorOS 13 实测）

### 13.1 到点提醒方式
提醒到点时像闹钟一样响铃，而不是普通通知提示音：
| 项 | 设计 |
|---|---|
| 声音 | 用户设置的闹钟铃声，`USAGE_ALARM`（闹钟音频流），使用当前闹钟音量；静音 / 振动模式下也响；不强制调大音量、不干预勿扰（与“查找手机”不同） |
| 时长 | 循环播放 + 振动，最多 1 分钟；暂停音乐等其它声音（音频焦点） |
| 实现 | `ReminderRingService` 前台服务（闹钟广播触发时系统允许启动前台服务）；无法启动时退回普通通知 |
| 停止 | 全屏卡片或通知上的“知道了 / 完成 / 10 分钟后”、删除提醒、在 App 中勾选完成；超时无人处理则转为静默通知留在通知栏 |
| 锁屏显示 | 点亮屏幕 + 全屏提醒卡片 `ReminderAlertActivity`（showWhenLocked / turnScreenOn） |

### 13.2 实测发现的问题与处理
| 现象 | 原因 | 处理 |
|---|---|---|
| 到点“没响” | 原方案使用通知提示音，只“叮”一声；该机通知音量仅约 1/4，且 ColorOS 默认不开横幅 | 改为闹钟流持续响铃（闹钟音量独立且通常较大） |
| 全屏卡片不出现、不亮屏 | ColorOS 把应用级通知重要性锁定为“默认”（`mIsAppImportanceLocked=true`），全屏通知要求“重要”级别，因此被忽略 | ① 服务自己用 `SCREEN_BRIGHT_WAKE_LOCK + ACQUIRE_CAUSES_WAKEUP` 点亮屏幕；② 获得“悬浮窗”权限时由服务直接启动全屏卡片 |
| 后台无法弹出卡片 | Android 10+ 限制后台启动界面；悬浮窗权限是常见的豁免条件 | 设置页新增“锁屏时弹出全屏提醒”，跳转系统授权页 |
| 首次弹出时出现系统对话框“需要在锁屏上显示” | ColorOS 额外的“锁屏显示”权限 | 用户点“允许”一次即可，此后直接在锁屏上显示 |
| 精确闹钟有延迟 | ColorOS 为精确闹钟设置了 20～50 秒的对齐窗口 | 系统行为，无法由应用控制；实测延迟在 1 分钟以内 |
| 到点被系统拦截 | ColorOS 后台管控 | 用户需开启“允许完全后台行为”“允许应用自启动” |

### 13.3 首次使用的权限清单（ColorOS）
1. 通知：允许；通知管理中勾选“横幅”“锁屏”
2. 应用管理 → 耗电管理：允许完全后台行为、允许应用自启动
3. App 内 设置 → 锁屏时弹出全屏提醒：授予“悬浮窗”
4. 首次全屏提醒时系统询问“锁屏显示”：允许

### 13.4 时间选择
系统表盘式 `TimePickerDialog` 内外圈（0–12 / 13–23）易误触，改为：
- 一键快捷时间：10 分钟后 / 30 分钟后 / 1 小时后 / 今晚（明晚）20:00 / 明早 09:00；
- 底部滚轮（`DateTimePickerSheet`）：日期（今天 / 明天 / 后天 / M月d日 周X）、时、分三列，实时显示“X 小时 Y 分钟后提醒”。
